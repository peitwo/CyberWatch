# CyberWatch V0.4.2 收尾修复报告：归档中心长标题撑宽表格

- 分支：`feature/status-history`（未切换、未合并）
- 范围：**只修归档中心标题列的宽度问题**，V0.4.2 功能范围就此冻结
- 结论：修复完成。pytest **141 passed / 0 failed**；真实 Chrome **251 / 251 项通过**（含本轮新增 49 项）
- 未 commit、未 push；真实库 `cyberwatch.db` 全程只读（mtime 仍为 `2026-10-16 01:31:27`、版本 `0002`、3 行数据、无 `deleted_at`）

## 一、根因

归档表 6 列（ID / 事件名称 / 等级 / 状态 / 归档时间 / 操作）中，**只有标题列没有任何宽度约束**（全局 CSS 只给主事件表的第 5 列「描述」加了 `max-width`，归档表的标题正好落在第 2 列，恰好躲过了所有限宽规则）。结果：

- 标题列被内容撑到 **235px**，表格总宽 **735px**，超出容器 **39px**（桌面 1440px 下容器为 696px）；
- 长标题还会**逐字换行**（实测 5 行），把行高从 68px 抬到 **120px**。

## 二、修改内容

只改两个文件、共 5 行，全部限定在归档表范围内。

| 文件 | 改动 | 说明 |
|---|---|---|
| `static/dashboard.css` | +3 行（L90–L93） | 新增 `.archive-scroll th:nth-child(2),.archive-scroll td:nth-child(2){max-width:190px}` 与 `.archive-scroll td:nth-child(2){white-space:nowrap;overflow:hidden;text-overflow:ellipsis}` |
| `static/dashboard.js` | 改 1 行 + 增 1 行（L117、L122） | 渲染循环改为带下标遍历；标题列（index 1）补 `td.title` 原生悬浮提示 |

**未改动**：任何后端代码（0 个 `.py`）、任何 API、任何测试文件、`templates/dashboard.html`、数据库结构与 Alembic 迁移。表格容器 `.table-scroll{overflow:auto}` 原样保留，横向滚动能力未动。

### 190px 这个值怎么来的

桌面下容器为 696px，其余 5 列实测占 **499px**（45+79+79+141+155），留给标题列的余量是 **197px**。取 **190px** 既能让表格完整落在容器内（不再出现多余横向滚动条），又留出亚像素余量。

## 五、已知限制

1. **190px 上限下，约 13 个汉字以上的标题就会被截断**。这是桌面容器（696px）扣掉其余 5 列（499px）后的硬约束；标题的完整内容依赖「详情」弹窗与悬浮提示两处补充。若要显示更长标题，需要加宽归档弹窗（`#archive-dialog` 现为 `min(95%,760px)`），属本轮范围之外。
2. **换行改为单行截断后，行高固定 68px**，归档表一屏可显示的行数比旧行为更多；这是本次修复的附带效果，未额外调整行高。
3. **窄屏仍横向滚动**：归档表 `min-width:620px`、主事件表 `min-width:1000px` 未改，走 `.table-scroll` 容器内滚动（页面本身不横向溢出）。这是既有设计而非缺陷。
4. **主事件表的标题列同样没有宽度上限**，长标题会撑宽该表 —— 因本轮要求「不修改其他 UI 模块」而**未处理**，留待后续版本评估。
5. 仅验证 Chrome（当前 251 项均为 Chrome 实测）；未覆盖 Safari / Firefox / 真机；未验证 320px 及以下视口；键盘焦点与 WCAG 对比度未系统验证。
6. 归档中心仍无搜索 / 筛选 / 排序 / 跳页；总数只在打开、归档 / 恢复动作与点「刷新」时更新。
